The Problem This Solves

Did every page actually change?

An AEP release touches hundreds of pages across three languages. Some pages get new plan details, some get a new Summary of Benefits PDF, some are supposed to change and quietly don't.

Checking that by hand isn't realistic. This tab takes a dated record of the site — called a snapshot — before and after, then tells you exactly what changed and, more importantly, what didn't.

You'll find AEP Launch in the tab bar when you're signed in as an Admin. Authors don't see it.
Step One

Pick which situation you're in

The tab has two separate workflows. They don't overlap — use whichever matches where you are in the release.

Before the release

Pre-launch validation

Answers: is the new content correct and complete?

Use it when the new content is staged and you want to see what's about to go live — and catch anything missing before customers do.

After the release

Post-launch verification

Answers: did every update actually land?

Use it when the release is live and you need to confirm nothing was missed — especially pages that were supposed to change but look untouched.

Step Two

Narrow it down to the pages you care about

Both workflows share a Section scope box. Type a section name and the tool only looks at those pages — much faster than scanning the whole site.

Type medicare and it covers every Medicare page in all three languages automatically. You don't add /es/ or /zh/ — each page is checked across languages as one unit.

A counter beside the box shows how many pages currently match, so you know your scope is right before you start.

Why PDFs get their own treatment

A page can swap its Summary of Benefits or formulary for a completely different file without a single word on the page changing. That's invisible in a normal text comparison, so linked documents are tracked separately — and shown as actual thumbnails of the first page, side by side, so you can see at a glance that the right document was attached.

There's also a dedicated Linked documents changed list that catches exactly this case: a swapped PDF on a page whose text didn't change at all.

What if a document won't display?

You'll see a small icon instead of a thumbnail, and each one means something specific: a crossed circle means the file is gone (a broken link), an arrow leaving a box means the file is somewhere the tool isn't allowed to reach, and a question mark means it downloaded but couldn't be opened. Word, Excel and PowerPoint files always show a plain file icon — browsers can't preview those.

Why do some comparisons only show a word count?

Detailed comparisons need both snapshots to have captured the page content. Snapshots taken before this feature existed don't have it, so those comparisons fall back to a simple word-count difference and say so. Take a fresh snapshot and the detail comes back.

Snapshots

Where your captures live

The whole team shares one library

Snapshots are saved centrally, not on your computer. A capture taken by a colleague shows up in your list, so one person can baseline before a deploy and someone else can verify afterwards. You can rename any snapshot by editing its label — useful for things like "Before AEP 2027 deploy".

Production and staging can't be mixed up

Each snapshot records which environment it came from automatically, based on the run that created it. That's why the comparison dropdowns only offer valid choices: production on the left, staging on the right for pre-launch, and production only for post-launch verification.

If a capture doesn't save

You'll get a clear message with a Retry save button. The results are still held in memory at that point, so retry before starting another run — otherwise you'll need to capture again.

Compare snapshots that used the same section scope. If they don't match, the tool warns you at the top of the results, because the "new" and "removed" counts will be misleading.
